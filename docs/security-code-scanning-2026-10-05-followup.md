## Additional fixes

- **MCP admission and pending work.** `/mcp`, `/mcp/hello` and `/mcp/session` were outside the gateway's central request budgets. A local caller could flood launcher nonces; a paired app could enqueue expensive tools and approval requests. All three routes now receive admission checks before body parsing, and launcher handshakes use the credential budget. Tool lists and calls share a budget per paired app, including individual batch members, with at most eight pending calls per app and 32 overall. Disconnecting does not release a slot until the underlying work ends. Protocol initialization and notifications remain available under HTTP admission limits.
- **Mock webhook destinations and admission.** Explicit mock mode exposed configurable delivery targets with public fixture credentials. Being bound to loopback did not prevent a web page or local program from trying to use those targets as a proxy. Teams, WeChat, Twilio, LINE and Google Chat now deliver only to the independently injected channel-door origin and a validated hook path. Redirects are refused, requests have a 15-second deadline, and replies are capped at 1 MiB. The six affected mock servers reject browser origins and unexpected Host headers, share rate and concurrency limits, and apply HTTP deadlines. These remain development fixtures with known credentials; the controls do not turn them into production services.
- **Discord's first heartbeat.** The first jittered heartbeat did not mark its acknowledgement as outstanding. A regression test reproduced delayed recovery when that first heartbeat was not acknowledged. It now reconnects at the next heartbeat interval, as subsequent heartbeats already did. The existing resume destination guard was also tested against a different loopback port.
- **Test fixtures.** The two browser test HTTP servers now escape request paths before writing HTML. TLS listener tests trust an explicit test CA and verify names; the optional Pebble test trusts the chain obtained over its authenticated ACME connection. Certificate serial generation uses unbiased `randomInt`. Redundant installer replacement, loose URL matching and incomplete tag assertions were corrected.
- **Evidence for retained safe behavior.** Tests exercise malformed Markdown through the real documentation head writers, Gmail authorization generations across reconnection, inert Matrix string responses and bounded sync delays. Matrix media responses additionally carry attachment, sandbox and nosniff headers.

No runtime dependency, new privilege setting, persisted file or security-checkup exception was added. No CodeQL rule was disabled and no source suppression was introduced.

## Decisions for every open alert

“Corrected” describes a source change to be re-evaluated by the next scan. “Verified false positive” means the reported weakness is absent in the reviewed data flow. A custom guard may still be reported by CodeQL. Such an alert should be dismissed only after confirming that its latest flow remains covered, with the implementation and test evidence attached to the alert. The repository owner authorized those evidence-backed dismissals; genuine unresolved findings remain open.

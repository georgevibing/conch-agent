# Code scanning review — 5 October 2026

The [second audit](./security-code-scanning-2026-10-05-followup.md) revisits all remaining alerts, fixes the deferred mock and test issues, and records the subsequent triage decisions. This first-pass report is retained as a historical snapshot.

Reviewed all **120 open CodeQL alerts** in `georgevibing/conch-agent` at commit `382a01e82b2dbf276bee680962a4602cdccd4c1b` (JavaScript/TypeScript analysis `1896005990`, CodeQL 2.27.1). The Actions analysis had zero findings. This is an implementation review of that snapshot, not a claim that GitHub has closed every alert.

## Priorities and threat model

The changes prioritize availability and credential boundaries in production: provider-controlled Discord reconnects and heartbeats, WeChat XML parsing, long labels/tool names/passwords, and gateway request floods. The gateway already enforces Host, Origin, sign-in and device approval; the new budgets add resource protection without granting access. A proven local browser keeps a separate recovery budget. No new privilege switch, persisted file, runtime dependency or checkup exception was introduced.

Additional hardening makes Google account lookups require own properties, escapes an inline script boundary, uses unbiased server IDs and handles Markdown backslashes. These findings had narrower reach than their scanner labels suggest.

Explicit mock mode runs separate loopback fake services. Their configurable webhook targets and test credentials are useful fixtures, but they are not hardened against hostile local clients. Mock-only SSRF/rate-limit work and two ephemeral browser test HTML sinks are deferred. Production never starts those mock listeners. No finding is silently suppressed or dismissed by this change.

## Review decisions

“Fixed” and “Mitigated centrally” describe tested source behavior. “Hardened” adds protection where existing constraints limited exploitability. “False positive” is supported by the data flow described below. GitHub CodeQL may retain alerts for the custom limiter because its query models recognized middleware libraries, not this implementation.

## Verification

- Regression tests exercise the attack inputs, not only normal use: near-miss XML, hostile resume destinations, invalid/duplicate heartbeats, long strings, inherited accounts, script terminators, concurrent HTTP bursts and identity rotation.
- Focused checks passed: 80 channel tests; 51 protocol/Nacre tests; 104 Google/artifact/provider/tool/report tests. The final gateway limiter suite passed 10 abuse tests, with its Google/provider integration run passing 62 tests. The final whole-repository `pnpm check` passed formatting, lint, type checks and 6,556 tests (18 skipped). It ran on Node 24 with `TMPDIR=/private/tmp` to avoid macOS’s `/var` symlink alias, and temporary sleep prevention after an earlier run was interrupted by system sleep.
- The production web build and five browser journeys passed using the installed Chromium-based browser: first conversation, stop, chat naming, password sign-in/pairing/sign-out, and security headers.
- Corrected a pre-existing macOS-only sandbox test assumption: the OS can initialize its own text-encoding variable with an empty child environment. A valid parent sentinel now verifies non-inheritance; production runtime code and the real app’s empty environment facade remain unchanged.
- Preserved concurrently landed fixes for two pre-existing test races exposed by the full run: tab restoration gets an explicit browser-start deadline, and the skill-learning fixture waits for cancellation writes before removing its temporary home. The security fixes were rebased onto `dc94481a`, preserving the new search and passkey changes, and the combined version passed the full check.
- Visually checked four Storybook screenshots from `scripts/snap.mjs`: PathPicker and ToolCall in light and dark themes, with lustre off. No UI layout or styling changed. No live provider account was contacted by these regression tests.
- Re-run GitHub CodeQL on the pushed commit to observe scanner closure separately from the behavioral checks.

# Code scanning review — 19 October 2026

A review of the CodeQL alerts open in `georgevibing/conch-agent` on 19 October 2026, following the [5 October review](./security-code-scanning-2026-10-05.md) and its [follow-up](./security-code-scanning-2026-10-05-followup.md). Each row says what was decided and the evidence for it. A fix is a change to the code, with a regression test that runs the attack; no alert is dismissed here. GitHub closes a fixed alert on the next analysis of `main`.

| [#133](https://github.com/georgevibing/conch-agent/security/code-scanning/133), [#163](https://github.com/georgevibing/conch-agent/security/code-scanning/163), [#189](https://github.com/georgevibing/conch-agent/security/code-scanning/189), [#200](https://github.com/georgevibing/conch-agent/security/code-scanning/200) `js/polynomial-redos` (`protocol/activity-describe/words.ts`, `dashboards.ts`, `memory.ts`, `switching.ts`)                                                               | Fixed                   | `^Couldn['’]t\s+(.+)$`, `=+$`, `[\s,.;:–—-]+$` and `\s*\(recommended\)\s*$` were quadratic on long runs of spaces, `=` or punctuation followed by something else (40,000 characters took about 0.7 s). They are replaced by index scans in `protocol/src/scan.ts` (`afterSpace`, `trimEndWhere`) and `withoutRecommended`. `scan.test.ts` compares each with the old expression on every short string over the characters that matter and on fast-check random strings, times 100,000–200,000-character near misses, and checks that none throws.                                                                                                                                                                                             |
| [#130](https://github.com/georgevibing/conch-agent/security/code-scanning/130), [#147](https://github.com/georgevibing/conch-agent/security/code-scanning/147) `js/polynomial-redos` (`nacre/FolderBrowser.tsx`, `nacre/Recipe/recipe.ts`)                                                                                                                                                                                                                                                               | Fixed                   | `withLastPart` cuts a typed path at its last separator. V8 already ran `[^\\/]*$` quickly, so this one is hardening, and it also stops `$&` in a folder's name being read as a replacement pattern. `withoutAsides` replaces `\(.*?\)`, which was quadratic on unclosed brackets. Its adversarial test also found that a very long ingredient made `new RegExp(\b…\b)` too big to build, which crashed the card. Whole-word matching now works by index (`hasWords`), and naming words longer than 60 letters are skipped. All three are compared with the old expressions on every string up to 6–7 characters and timed on near misses of 200,000–500,000 characters.                                                                       |

The agent writes this command line. `stripTimeout` reads each word once, from the last back, and prefers the same reading the expression did. `risk-scan.test.ts` compares it with the old expression on every short line and on 5,000 fast-check lines, and times 50,000 repeats through `commandParts`.                                                                                                                                                                                                                        |
